# DART 공시 → 마크다운 변환기

DART 공시 원문을 AI가 읽기 좋은 마크다운으로 바꿉니다.

Python만 있으면 됩니다. 설치할 라이브러리가 없습니다.

---

## 쓰는 법

`3.공시` 폴더에서 이 한 줄만 실행하면 됩니다.

```bash
python parser/rag_pipeline.py corpus/raw corpus/rag corpus/manifest.jsonl
```

`corpus/rag/` 에 마크다운 **4,616개**가 만들어집니다.

### 옵션

| 옵션 | 설명 |
|---|---|
| `--limit 30` | 앞에서 30개만 (미리보기) |
| `--keep-empty` | 값이 `-` 인 항목도 남김 (기본은 뺌) |
| `--with-sector` | 업종 뒤에 섹터를 덧붙임 |
| `--no-old-name` | 옛 사명을 동의어에 안 넣음 |
| `--groups holding,periodic` | 특정 문서군만 변환 |

## 파일 역할

| 파일 | 역할 |
|---|---|
| **`rag_pipeline.py`** | **실행하는 것.** manifest를 읽어 헤더를 붙이고 저장 |
| `exchange_parser.py` | 부품 — 거래소공시 HTML 변환 |
| `major_parser.py` | 부품 — 주요사항보고서 XML 변환 |
| `holding_parser.py` | 부품 — 대량보유상황보고서 XML 변환 |
| `periodic_parser.py` | 부품 — 사업/분기/반기보고서·감사보고서 XML 변환 |

부품 4개는 **같은 폴더에 있어야 합니다.** 지우면 안 됩니다.

holding_parser.py·periodic_parser.py는 major_parser.py와 같은 골격(관대한
HTML 파서, 셀 모델, 행 분류 알고리즘)을 쓰되, 원문을 전수 훑어 확인한 사실에
맞게 두 가지를 더했습니다.

1. **머리글 없는 표의 진짜 머리글 찾기.** `<THEAD>` 없이 배경 음영
   (`USERMARK` 안 `BC0X...` 코드)만으로 머리글을 표시하는 표가 있습니다
   (재무제표 주석 표에 아주 흔함). 이 신호는 TD에만 붙고 TE/TU에는 전혀
   안 붙습니다. 놓치면 "구분1/구분2/…" 같은 가짜 머리글로 "당기말 유동"
   같은 실제 항목명이 사라집니다. periodic 전체에서 43,998번 이 규칙이
   실제 머리글을 살렸습니다.
2. **행마다 따로 colspan을 지웁니다.** major_parser.py는 표 전체에서
   "모든 행에 걸쳐 옆칸과 완전히 같은 열"만 지우는데, 표지 레터헤드처럼
   합쳐진 칸의 위치가 행마다 다르면 이 조건이 안 맞아 글자가 중복
   출력됩니다. 행 하나 안에서만 판단하도록 바꿨습니다.

### 헤더 3줄이 하는 일

검색할 때 걸리게 하는 용도입니다.

- **표준사명 / 종목코드 / 업종** — 필터 검색용
- **동의어** — 사용자가 `대우조선해양` 으로 검색해도 `한화오션` 문서가 잡힘

옛 사명은 자동으로 동의어에 들어갑니다.

### 동의어는 문서군 4개를 통틀어 같습니다

회사명이 담기는 자리가 문서군마다 다릅니다 — exchange는 HTML `<title>`
(공시 당시 표시명, 약칭 위주), major/holding/periodic은 XML
`<COMPANY-NAME>`(정식 등기 법인명, 전체 표기)을 씁니다. 문서 한 건만
보고 동의어를 만들면 "에이치엠엠 주식회사"로 검색했을 때 HMM의
periodic·major·holding 문서는 걸리는데 exchange 문서는 하나도 안
걸리는 식으로 문서군마다 결과가 달라집니다.

그래서 저장하기 전에 `corpus/raw` 전체를 한 번 가볍게(표·문단 처리
없이 회사명 태그 하나만) 훑어서, 회사(`corp_code`)별로 네 문서군에서
나온 이름 표기를 전부 모읍니다(`CompanyAliasRegistry`). 그 다음 문서군에
상관없이 같은 회사면 같은 동의어 목록을 붙입니다. 예를 들어 HMM은
`(주)HMM, HMM주식회사, HMM, 에이치엠엠, 에이치엠엠 주식회사,
에이치엠엠(주), 에이치엠엠㈜, 에이치엠엠주식회사` 8개 표기가 네
문서군 파일 전부에 동일하게 붙습니다.

`--no-unify-aliases` 를 주면 예전처럼 문서 하나 자체의 옛 이름만 씁니다.
이 방식은 `raw_root` 로 `corpus/raw` 전체를 넘겨야 효과가 있습니다 —
특정 문서군 폴더 하나만(예: `corpus/raw/periodic`) 넘기면 다른 문서군의
표기를 모을 수 없습니다.

## 알아둘 점

### 값이 `-` 인 항목은 기본으로 뺍니다

공시 서식에는 안 쓰는 칸이 많습니다. 그대로 두면 지저분해집니다.

원본을 다 남기려면 `--keep-empty` 를 쓰세요.

단 `해당사항없음` / `미해당` / `해당` / `아니오` 는 **뜻이 있는 답이라 항상 남깁니다.**

### 인코딩

원본은 전부 UTF-8 입니다. 다만 거래소공시 HTML 에는 `charset=euc-kr` 이라고
**잘못 적혀 있습니다.** 적힌 대로 믿고 읽으면 전부 깨집니다.
이 변환기는 적힌 걸 무시하고 바이트를 직접 확인합니다.

### DSD-XML(major/holding/periodic)은 정식 XML 이 아닙니다

본문에 `<별표3-3>` 같은 꺾쇠나 이스케이프 안 된 `&` 가 그대로 들어있는 문서가
많습니다. 정식 XML 파서를 쓰면 이런 문서가 조용히 깨지거나 사라집니다.
그래서 관대한 HTML 파서(`html.parser`)를 씁니다 — `<` 다음이 영문자일 때만
태그로 보고, 한글/숫자/기호가 오면 그냥 글자로 남기기 때문에 이런 문서도
안 깨집니다.

### DSD-XML의 라벨/값 신호

`TD`/`TH` = 라벨, `TE`/`TU` = 값입니다. `TE`는 전부 `ACODE`를,
`TU`는 전부 `AUNITVALUE`를 갖고 있어 DART 필드코드를 그대로 살릴 수
있습니다(`--json` 산출물의 `필드코드`). 다만 `<THEAD>` 있는 표 안에서는
`TD`도 라벨이 아니라 데이터입니다 — 표 하나 단위로 먼저 판단합니다.

### periodic은 한 접수번호에 원문이 여러 개일 수 있습니다

본보고서 + 감사보고서(00760) + 연결감사보고서(00761)처럼 최대 3개까지
같은 접수번호 폴더 안에 있습니다. `periodic_parser.py`는 파일 하나만
처리하고, 여러 파일을 하나의 접수번호로 묶는 것은 `rag_pipeline.py`의
파일 이름 규칙(`_00760` 꼬리)이 담당합니다.

## 본문 손실 검증 (holding/periodic, 2026-08-13)

exchange/major는 아직 이 방식으로 검증하지 않았습니다. holding·periodic은
"원문 글자가 실제로 다 옮겨졌는가"를 두 가지 방법으로 확인했습니다.

1. **토큰 비교** — 원문에서 태그만 지운 글자와 결과 md의 글자를 각각
   3자 이상 한글/영숫자 토큰 집합으로 만들어 대조 (65개 표본).
   최종 평균 손실 0.12%, 남은 손실은 전부 의도적으로 뺀 것(이미지
   파일명, `<SUMMARY>` 메타데이터)으로 확인.
2. **구조 직접 대조** — 칸에 글자가 있는데 결과 조각이 0개인 표(표
   전체 소실), 원문 `<TITLE>` 개수 대비 산출 제목 개수를 100개 표본에
   직접 셈. **표 소실 0건, 제목 15% 이상 비는 문서 0건.**

이 과정에서 실제 버그 4개를 찾아 고쳤습니다.

| # | 문제 | 규모 | 원인 |
|---|---|---|---|
| 1 | 재무제표 주석 제목이 통째로 사라짐 | HMM 분기보고서 표본 1건에서 제목 136개 중 83개(61%) | `<TITLE>`이 `SECTION-N`/`COVER`/`CORRECTION` 바로 밑에만 있다고 가정하고 그 외(`TABLE-GROUP` 등)에 있으면 전부 "이미 처리한 것"으로 보고 건너뜀 |
| 2 | 감사보고서 표의 마지막 값이 사라짐 | periodic 전체 208,861건 | 라벨-값을 번갈아 묶는 로직이 행이 값으로 끝나고 그 값의 라벨이 같은 행에 없으면(위쪽 행에 rowspan으로만 걸림) 마지막 값을 버림 |
| 3 | 굵은 소제목이 다음 문장에 그대로 들러붙음 | 표본 다수 | `<SPAN>나. 소수주주권</SPAN>회사는...`처럼 원문에 공백이 없으면 "나. 소수주주권회사는"으로 붙어 회사명처럼 오독됨 |
| 4 | "부터"/"까지" 같은 접미사 라벨이 사라짐 | 거의 모든 periodic(사업연도 표) | `L V L`로 행이 끝나면(예: 사업연도/값/부터) 앞의 L-V만 짝짓고, 값 뒤에 남는 라벨은 "짝지을 값이 없다"고 그냥 버림. 값 자체는 안 빠지고 접미사만 빠져서 앞서 65개 표본 토큰 비교(3자 미만은 안 봄, 집합 비교라 같은 낱말이 딴 데 있으면 안 걸림)로는 못 잡았고, 사용자가 직접 파일을 열어보고 알려줌 |

3번을 고치면서 한 번 더 실수했습니다 — 태그 경계가 아니라 **모든** 글자
조각 사이에 공백을 넣었더니, `html.parser`가 이스케이프 안 된 `&`
때문에 쪼갠 조각(`P&A인수하여` → `P` / `&A인수하여...`)에도 공백이
끼어 "P &A 인수하여"로 깨졌습니다. 태그에서 나온 조각과 맞닿을 때만
공백을 넣도록 다시 고쳤습니다. 이것도 사용자가 직접 확인하다가 발견함.

### 표 단위 정밀 대조 (3차 검증)

앞의 토큰 비교는 **문서 전체** 단어 집합으로 대조해서, 빠진 낱말이 문서
다른 곳에 우연히 있으면 못 잡는 사각지대가 있었다(실제로 4번 버그는
이 방식으로 못 잡고 사용자가 직접 찾음). 그래서 범위를 표 하나로 좁혀
다시 돌렸다: 표 하나의 각 칸 글자(짧은 단어 포함, 토큰화 안 함)가
**그 표 자신이 만든 출력 안에만** 있는지, `--keep-empty`로 `-` 값까지
빼놓지 않고 대조. holding·periodic 2,549건 전체 대상.

결과: 놓친 칸 6,349개 발견 → 전수 분석 결과 전부(100%) `_colon_kv`가
"회 사 명 :" 같은 글자 사이 벌어진 라벨을 "회사명"으로 다듬으며 공백·콜론을
지우는 **의도된 동작**이었다. 값은 전부 정상적으로 붙어 나온다. 그 외
원인으로 놓친 칸은 **0건**.

| 검증 | 상태 |
|---|---|
| 문서 식별 정보 (회사·종류·정정) | ✅ 외부 기준과 100% 일치 (전체) |
| 행·표 분류 완결성 | ✅ 미분류 0 (전체) |
| 본문이 빠짐없이 옮겨졌는가 | ✅ holding/periodic 3중 확인(토큰 비교·구조 대조·칸 단위 정밀 대조). exchange/major 미실시 |
| 표가 내용을 다 담았는가 | ✅ holding/periodic 칸 단위 정밀 대조로 확인. exchange/major 미실시 |
| 없는 내용을 지어내지 않았는가 | ❌ 미실시 (전체) |
