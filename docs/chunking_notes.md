# 청킹 전 알아야 할 것 — 제목 계층과 표

마크다운의 `#` 계층과 표를 기준으로 조각을 나눌 때 **먼저 읽어야 하는 문서**다.
계층이 어떻게 만들어지는지, 어디까지 믿어도 되는지, 무엇을 믿으면 안 되는지를
전수 실측으로 적는다.

측정 대상은 `data/interim/docs/` 4,201문서(part 4,616개)와 거기서 나온
조각 1,290,417개다. 재현은 이 문서 맨 아래.

---

## 1. 계층은 어디서 오는가

`#` 레벨은 파서가 붙인 `('h', 레벨, 글자)` 조각에서 그대로 나온다
([render/markdown.py](../src/render/markdown.py)). 그런데 그 레벨을 정하는
곳이 **네 군데**고, 서로 다른 규칙을 쓴다.

| 출처 | 레벨 | 코드 |
|---|---|---|
| `SECTION-1` ~ `SECTION-4` | 2, 3, 4, 5 (고정 매핑) | [normalize/tree.py](../src/normalize/tree.py) `SECTION_TAGS` |
| `COVER` / `CORRECTION` | 2 (고정) | `*_parser.py` `_walk` |
| 떠 있는 `TITLE` 노드 | `min(max(depth+1, 2), 6)` — **깊이에서 유도** | `*_parser.py` `_walk` |
| 표 안 라벨 행 (한 칸이 행 전체를 차지) | **4 (고정)** | [periodic_parser.py:538](../parser/periodic_parser.py#L538) 외 |
| 1칸 표 강등 (제목 모양일 때) | `min(depth+1, 6)` | `_one_cell` |

`h1`은 **조각에 없다.** 문서 제목(`# [삼성전자] 분기보고서 (2023.03)`)은
렌더러가 헤더로 따로 붙인다. 그래서 **본문 계층은 h2에서 시작한다.**

---

## 2. 믿어도 되는 것 (전수)

| 항목 | 결과 |
|---|---|
| 제목이 하나도 없는 part | **0 / 4,616** |
| 첫 제목 앞에 나온 조각(고아) | **0개** |
| 빈 제목 | **0개** |
| 첫 제목의 레벨 | 네 문서군 **전부 h2** (예외 0) |
| 레벨 건너뜀 (`cur > prev+1`) | 3,204건 (0.6%) — **전부 `h2 → h4`, holding 한 종류** |
| 조각의 `section_path` 가 빈 것 | **0개** |

건너뜀 3,204건은 holding 의 `(약식서식 : 자본시장과 금융투자업에 관한 법률
제147조에 의한 보고 …)` 서식 안내 문구 하나다. 문서 구조가 깨진 게 아니라
그 문구가 표 라벨 행(고정 h4)으로 잡혀 SECTION-1(h2) 바로 뒤에 오는 것이다.

## 3. 믿으면 안 되는 것 세 가지

### ① h4는 두 가지가 섞여 있다 ★

표본 60문서(periodic/holding/major 각 20)에서 제목의 출처를 갈라 세면:

| 출처 | h2 | h3 | h4 | h5 |
|---|---:|---:|---:|---:|
| SECTION / TITLE 구조 | 411 | 810 | 977 | 61 |
| **표 안 라벨 행 (고정 h4)** | 0 | 0 | **1,128** | 0 |
| 1칸 표 강등 | 0 | 40 | 13 | 30 |

**h4의 53%가 문서 구조가 아니라 표 안 라벨 행이다.** 전체 제목의 34.9%가
표에서 나왔다. 코드에 `('h', 4, …)` 로 **고정**되어 있어서 그 표가 문서의 몇
단계에 있든 4로 찍힌다.

- 청킹 **경계**로 쓰는 것은 좋다 — 그 라벨은 사실상 그 표의 제목이라,
  `section_path` 마지막 마디가 표 이름 역할을 한다.
- 청킹 **깊이**로 쓰면 틀린다 — `h4 = 문서의 3단계 섹션` 이 아니다.

### ② 크기 편차가 극단적이다 — 제목만으로는 못 자른다

`section_path` 마디 하나에 묶이는 글자 수 (묶음 141,667개):

| | 글자 수 |
|---|---:|
| 중앙값 | 1,704 |
| 평균 | 5,437 |
| p90 | 10,750 |
| p99 | **64,072** |
| 최대 | **1,174,861** |

5만 자를 넘는 묶음이 **2,116개**다. 최악의 예:

| 글자 수 | 경로 |
|---:|---|
| 1,174,861 | `주식등의 대량보유상황보고서 > 제3부 … > 2. 세부변동내역 > 가. 주식등의 세부변동내역` |
| 1,069,226 | `사 업 보 고 서 > III. 재무에 관한 사항 > 3. 연결재무제표 주석 > 2.1 …` |

재무제표 주석과 세부변동내역은 제목 하나 밑에 수천 행짜리 표가 통째로 들어앉는다.
**표 단위 2차 분할이 필수**다. 지금 [chunk/build.py](../src/chunk/build.py) 는
`MAX_TABLE_ROWS = 40` 으로 쪼개면서 **헤더와 문맥을 매 조각에 다시 붙인다** —
표 중간을 잘라 놓고 헤더를 안 주면 열이 무엇인지 알 수 없기 때문이다.

문서군별 묶음 크기 (중앙값 / p90 / 최대):

| 문서군 | 묶음 | 중앙값 | p90 | 최대 |
|---|---:|---:|---:|---:|
| exchange | 4,197 | 375 | 808 | 3,049 |
| major | 2,669 | 1,000 | 3,507 | 23,112 |
| holding | 18,906 | 584 | 2,257 | 1,174,861 |
| periodic | 115,895 | 2,227 | 12,470 | 1,069,226 |

### ③ 문단이 제목으로 올라온 것이 7,865개

60자를 넘는 제목이다. 예: `2.1 연결재무제표 작성기준 회사와 회사의 종속기업은 …`.
주석 본문 첫 줄이 라벨 행으로 잡혀 제목이 됐다. 내용이 사라진 것은 아니지만
경로 마디로 쓰면 지저분하다. 같은 제목이 연속으로 두 번 나오는 경우도 4,556건 있다.

## 4. `section_path` 조립 규칙

[chunk/build.py](../src/chunk/build.py) 는 제목을 만날 때마다

```python
section = section[:lvl - 1] + [c[2]]
```

로 경로를 갱신한다. 레벨이 2부터 시작하므로 **첫 마디(index 0)는 절대 밀려나지
않는다.** 결과적으로 경로의 첫 마디는 언제나 그 문서의 **문서 종류 제목**이 되고,
나머지 같은 레벨 형제들은 그 아래로 붙는다.

| 문서군 | 경로 첫 마디 (상위) |
|---|---|
| periodic | `분 기 보 고 서` / `사 업 보 고 서` / `정 정 신 고 (보고)` / `반 기 보 고 서` |
| holding | `주식등의 대량보유상황보고서` / `정 정 신 고 (보고)` |
| major | `주요사항보고서 / 거래소 신고의무 사항` / `정 정 신 고 (보고)` |
| exchange | `정정신고(보고)` / `단일판매ㆍ공급계약 체결` / … |

즉 **경로 깊이 = 제목 레벨 − 1** 이다. 깊이 분포는
1: 0.6% / 2: 4.3% / 3: 24.9% / **4: 66.0%** / 5: 4.2%.

정정공시는 `정 정 신 고 (보고)` 가 루트가 되고 본 보고서가 그 자식으로 들어간다
(periodic 215,119조각). 의도한 설계는 아니지만 의미상 틀리지 않아 그대로 둔다.

---

## 5. 그래서 청킹할 때

1. **h2 / h3 는 믿고 경계로 쓴다.** 순수하게 문서 구조다
   (SECTION-1/2, COVER, CORRECTION).
2. **h4 는 경계로만 쓰고 깊이로 해석하지 않는다.** 절반이 표 라벨이다.
3. **제목 경계와 표 행 수 상한을 반드시 함께 쓴다.** 제목만으로 자르면 p99에서
   6만 자, 최악 117만 자가 나온다.
4. **표를 쪼갤 때 헤더·단위·문맥을 매 조각에 다시 붙인다.** 이걸 안 하면
   숫자 표 조각의 78.9%가 단위를 잃는다(1단계 실측).
5. **`section_path` 를 다시 만들지 않는다.** 조각마다 이미 붙어 있고
   (빈 값 0개), 위 규칙대로 조립돼 있다.

---

## 6. 재현

```bash
python scripts/03_build_docjson.py --jobs 48     # 원문 → doc.json
python scripts/06_build_chunks.py --jobs 40      # doc.json → 조각
```

제목 레벨 분포·건너뜀·고아 조각은 `data/interim/docs/*.json.gz` 의
`parts[].doc.chunks` 에서 `('h', 레벨, 글자)` 를 세면 그대로 나온다.
묶음 크기는 `data/processed/chunks.jsonl.gz` 의 `section_path` 로 묶어 센다.
제목의 출처별 분류는 `_one_cell` 과 `_table` 을 감싸서 센 값이다
(파서는 건드리지 않는다).
