# 공시뷰어 HTML → 마크다운 (status 014 대체 경로)

DART OpenAPI가 `document.xml`을 안 주는 문서를, 공시뷰어 HTML에서 뽑습니다.

한화에어로스페이스 분기보고서(2026.03, 접수번호 `20260513000860`) 1건에 적용했습니다.

기본 경로는 `README.md`를 보세요. 이 문서는 **XML이 없을 때만** 타는 우회로입니다.

---

## 쓰는 법

```bash
python build_viewer_html.py
```

`results/rag/한화에어로스페이스_periodic_20260513000860.md` 가 만들어지고,
`rag_meta.jsonl` 에 넣을 한 줄이 화면에 찍힙니다.

경로는 `build_viewer_html.py` 상단 상수에 박혀 있습니다. 한 건짜리 작업이라
그렇게 뒀습니다. 다른 문서에 쓰려면 `RCEPT`·`SRC`만 바꾸면 됩니다.

## 파일 역할

| 파일 | 역할 |
|---|---|
| **`build_viewer_html.py`** | **실행하는 것.** 순서대로 시키고 저장 |
| `viewer_html_parser.py` | 부품 — 뷰어 HTML을 `periodic_parser`가 먹는 트리로 번역 |
| `periodic_parser.py` | 기존 부품 — 실제 마크다운 생성 (**수정 안 함**) |
| `rag_pipeline.py` | 기존 부품 — RAG 헤더 3줄 생성 (**수정 안 함**) |

`exchange_parser.py`·`major_parser.py`·`holding_parser.py`는 이 경로에서
일하지 않지만, `rag_pipeline.py`가 상단에서 4개 파서를 전부 import하므로
**같은 폴더에 있어야 실행됩니다.**

### 흐름

```
viewer.html  (이미 HTML — 변환 안 함)
   │  periodic_parser._TreeBuilder 로 DOM 생성   ← 파서 부품을 빌려 씀
   ▼
DOM
   │  viewer_html_parser 가 3군데 고침
   ▼
XML처럼 생긴 DOM
   │  periodic_parser._walk() → to_markdown()    ← 수정 없음
   ▼
본문 마크다운
   │  rag_pipeline.build_rag_header()            ← 수정 없음
   ▼
최종 .md
```

새로 쓴 건 가운데 "모양 고치는" 부분 하나뿐입니다. 트리 빌더도 마크다운
생성도 전부 기존 `periodic_parser` 것입니다. 그래서 결과물이 XML로 만든
다른 분기 파일 19개와 같은 모양으로 나옵니다.

## 왜 PDF가 아니라 HTML인가

status 014 문서 3건은 PDF + 뷰어 HTML로 대체 수집돼 있고, 원래는
**"뷰어 HTML은 껍데기이므로 PDF에서 파싱한다"** 로 판단돼 PDF 전용
파이프라인이 만들어졌습니다.

이 판단은 3건 중 2건에만 맞습니다.

| | 본문 텍스트 | `<table>` | `rowspan/colspan` | `<script>`/`<iframe>` | 판정 |
|---|---|---|---|---|---|
| KB금융 `20260619000667` | 699자 | 1 | 0 | 21 / 1 | 껍데기 |
| 한화오션 `20240514001522` | 420자 | 1 | 0 | 21 / 1 | 껍데기 |
| **한화에어로스페이스 `20260513000860`** | **503,667자** | **2,045** | **2,816** | **0 / 0** | **전문** |

한화에어로스페이스 파일만 다른 방식으로 수집됐습니다. 파일 헤더 주석에
그렇게 적혀 있습니다.

```
DART 전자공시 뷰어(report/viewer.do) 섹션을 목차 순서로 병합한 전문.
OpenAPI document.xml 미제공(status 014)에 따른 대체 수집본, 수집일 2026-07-06
```

3건을 한 묶음으로 판단하면서 이 파일이 껍데기로 오분류됐습니다.

### PDF가 추측하던 걸 HTML은 갖고 있습니다

| PDF 경로에서 하던 일 | HTML에 있는 것 |
|---|---|
| leaf cell bbox 교차점으로 rowspan/colspan 기하학적 복원 | `rowspan` 1,590 + `colspan` 1,226 명시 |
| "머리글 행은 안전하게 판별 불가 → 추측" | `<TH>` 3,452 + `<THEAD>` 555 명시 |
| PDF 북마크 → `SECTION-<N>` 레벨 매핑 | `class="section-1/2/3"` 명시 |
| 표지 정형 문구 정규식 추측 | `class="cover-title"`, `eleId` 속성 명시 |
| 세로 회전 텍스트 x좌표 판별 | 해당 없음 |
| 페이지 경계에서 잘린 텍스트 이어붙이기 | 해당 없음 |
| `dart.fss.or.kr Page N` 푸터 제거 | 해당 없음 |

PDF 작업에서 "원인이 달라 미수정으로 남긴" 결함 2건(한 셀에 숫자 여러 개
겹침, 각주 괄호가 별도 칸으로 분리)도 좌표 기반 파싱에서만 생기는 현상이라
HTML에서는 발생하지 않습니다.

## 번역기가 메우는 구멍 3가지

XML 원문과 뷰어 HTML의 뼈대 차이는 아래가 전부입니다.

| XML 원문 | 공시뷰어 HTML |
|---|---|
| `<SECTION-1><TITLE>제목</TITLE> …내용… </SECTION-1>` | `<P class="section-1">제목</P>` + 형제로 나열된 내용 |
| `<SECTION-3><TITLE>2-1. …</TITLE>` | `<P class="table-group-xbrl">2-1. …</P>` |
| `<COVER><COVER-TITLE>` | `<P class="cover-title">` |
| `<IMAGE><IMG><IMG-CAPTION>` | `<TABLE class="nb">` 안의 `<IMG>` |
| `<TE>` / `<TU>` (값 칸) | 없음 — 전부 `<TD>` |
| `THEAD`, `rowspan`, `colspan` | 그대로 있음 (변환 불필요) |

### ① 섹션 중첩 — `_restructure()`

뷰어는 섹션을 컨테이너로 감싸지 않고 제목 문단을 형제로 흘려놓습니다.
제목이 나온 지점을 경계로 뒤따르는 형제들을 그 섹션 안에 집어넣습니다.
스택으로 열고 닫으며, 같거나 더 얕은 레벨의 제목을 만나면 열린 섹션들을
그 자리에서 닫습니다.

`table-group`·`table-group-xbrl`(98개)도 제목 문단입니다 — 재무제표·XBRL
주석의 소제목이고 XML의 SECTION-3 자리에 대응합니다. 이게
`#### 2-1. 연결 재무상태표` 같은 제목을 복원합니다.

> 대조: `table-group*` 98 + `section-3` 2 = 100.
> 직전 분기(XML)의 level-4 heading은 101개.

### ② 값 칸 표시 — `_retag_value_cells()`

`periodic_parser._Cell.is_label` 은 `tag in ('TD','TH')` 로 판정합니다.
뷰어 HTML은 값 칸도 전부 `<TD>` 라서 그대로 넣으면 **모든 칸이 라벨**이
됩니다. 그 결과 표 한 줄짜리 캡션이 문단이 아니라 제목으로 승격돼
heading이 159개에서 379개로 부풉니다.

**테두리 없는 표(`class="nb"`)에서 행을 통째로 차지하는 단일 칸**만
`<TE>` 로 바꿉니다. 캡션·각주·단위 표기가 여기 옵니다 —
`연결 재무상태표`, `(단위 : 천원)`, `※ …`. 실측 419칸.

테두리 있는 표(실데이터 격자)는 건드리지 않습니다. 그쪽은 XML에서도 TD로
채워져 있고 머리글은 THEAD가 알려줍니다. 손대면 멀쩡한 표가 키-값 목록으로
흩어집니다.

### ③ 첨부 이미지 — `_convert_images()`

`<TABLE class="nb">` 안에 `<IMG>` 가 든 것을 `<IMAGE>` + `<IMG-CAPTION>`
노드로 바꿉니다. 캡션은 `<P class="img-caption">` 에서, 없으면
`alt="이미지: 확인서"` 에서 접두어를 떼고 씁니다. 결과는
`(첨부 이미지: 확인서)`.

## 시도했다가 버린 것 — `align` 기반 값 칸 판별

뷰어는 값을 오른쪽/가운데로 정렬해 그립니다. 신호 자체는 아주 깨끗했습니다.

| align | 칸 수 | 숫자 비율 |
|---|---|---|
| 없음 | 14,140 | **0.0%** |
| RIGHT | 19,304 | 50.8% |
| CENTER | 7,473 | 9.7% |

정렬 없는 칸 14,140개 중 숫자가 하나도 없습니다. 라벨과 값이 완전히
갈립니다.

**그런데도 버렸습니다.** 정렬은 값 칸과 상관이 높지만 XML의 TD/TE 경계와
같지 않기 때문입니다. 적용해보니 XML이 라벨로 두는 칸까지 값이 됐고,
한 줄로 붙어야 할 캡션 행이 키-값으로 흩어졌습니다.

```
레퍼런스(XML)     당분기말 | (단위 : 천원)
align 규칙 적용    - **당분기말**: (단위 : 천원)
```

kv가 50개에서 483개로 늘었습니다. 신호가 깨끗한 것과 그 신호가 우리가
원하는 경계인 것은 다른 문제였습니다.

`viewer_html_parser.py` 의 `_VALUE_ALIGNS` 상수가 그 흔적입니다. 지금은
쓰이지 않습니다.

## 검증 (2026-08-27)

**파서를 쓰지 않습니다.** 원문 HTML에서 정규식으로 직접 글자를 뽑아
대조합니다. 파서로 파서를 검증하면 같은 오해를 두 번 해도 통과합니다.
(`verify_markdown.py` 와 같은 원리)

빈 값이 생략되지 않도록 `drop_empty=False` 로 만든 마크다운과 비교하고,
파서와 검사기의 공백 처리가 서로 달라서(`<BR/>` 경계 등) 양쪽 공백을 모두
제거하고 대조합니다.

### ① 유실 — 원문의 글자가 마크다운에 있는가

```
원문 텍스트 단위 (중복 제거) : 12,716
마크다운에서 못 찾은 단위    :     10  (0.079%)
```

10건 전수 확인 결과 **실제 유실 0건**.

- 4건 — 검사기가 `<P>` 와 그 안의 중첩 표 텍스트를 한 덩어리로 묶은 오탐.
  조각별로는 모두 존재
- 5건 — `_colon_kv` 가 키로 흡수한 콜론 라벨(`회 사 명 :`). 값과 함께 정상 출력
- 1건 — `<head>` 의 `<title>`. 본문 아님

### ② 역방향 — 마크다운의 글자가 원문에 있는가

```
마크다운 텍스트 단위 (중복 제거) : 12,844
원문에서 못 찾은 단위            :    252  (1.96%)
```

252건 전부 `_real_table` 이 다단 머리글을 합성한 라벨(`항공 금액`,
`당분기 건물 및 구축물`). 기존 XML 결과와 같은 정상 동작.
**지어낸 내용 0건**.

## 알아둘 점

### 동의어는 형제 파일에서 읽어옵니다

동의어에는 manifest만으로는 알 수 없는 변형(`한화에어로스페이스(주)`)이
섞여 있습니다. 원래 `CompanyAliasRegistry` 가 raw 트리 전체를 훑어 모으는
값인데, 한 건 만들자고 1,054개 폴더를 다시 훑을 이유가 없어서 같은 회사의
기존 md에서 `> 동의어/검색어:` 줄을 읽어 가장 긴 목록을 씁니다.
결과적으로 20개 파일의 동의어 줄이 전부 같아집니다.

`sibling_aliases()` 가 하는 일입니다.

### 남은 차이 2건 (정보 손실 아님)

| 항목 | 내용 |
|---|---|
| `## 목 차` | 뷰어 HTML에는 목차가 없습니다(뷰어 UI 기능). 기존 XML 결과에서도 내용 없는 빈 heading |
| 사업연도 | 기존은 `- **사업연도 > 부터**: …`, 이 파일은 표 두 줄. 위 "버린 것" 판단의 결과이고 값은 그대로 들어 있습니다 |

### 껍데기는 이 경로를 못 탑니다

`looks_like_viewer_html()` 이 `<iframe>` 유무와 `class="section-N"` 존재로
걸러냅니다. `build_viewer_html.py` 는 껍데기면 즉시 중단합니다.

KB금융·한화오션은 진짜 껍데기라 기존 PDF 경로를 유지해야 합니다.
